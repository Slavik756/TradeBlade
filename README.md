# TradeBlade

Адаптивный лендинг сервиса копирования сделок. Интерфейс написан на HTML, CSS и
модульном JavaScript; Vite запускает локальный сервер и собирает
оптимизированную статическую версию.

## Локальный запуск

Требуется Node.js 22.12 или новее и npm. Проверено на Node.js 24.21.0.

```bash
npm ci
npm run dev
```

Откройте адрес, который Vite напечатает в терминале. По умолчанию это
`http://localhost:5173`. Не открывайте `index.html` через `file://`: JavaScript
использует модули.

```bash
npm run build
npm run preview
```

Первая команда создаёт готовый сайт в `dist/`, вторая позволяет проверить именно
эту сборку; стандартный адрес — `http://localhost:4173`.

## Структура

```text
index.html        Семантическая разметка и контент страницы
css/styles.css    Адаптивная сетка и состояния элементов
css/tokens.css    Цвета, типографика и общие параметры дизайна
js/core.js        Точка входа и инициализация поведения
js/modules/      Отдельные модули интерактивных элементов
img/             Локальные изображения и SVG
vite.config.js   Настройки сборки
```

Для одностраничного лендинга отдельный UI-фреймворк не требуется. Независимые
сценарии поведения собраны в небольшие модули; структура подходит для
последующего подключения API без переписывания всей страницы. Vite зафиксирован
в `package.json`, точные версии зависимостей — в `package-lock.json`. Установка
через `npm ci` воспроизводит этот набор.

## Размещение на Vercel

Импортируйте GitHub-репозиторий в Vercel со следующими настройками:

| Параметр         | Значение                                         |
| ---------------- | ------------------------------------------------ |
| Framework Preset | Vite                                             |
| Root Directory   | Корень репозитория, где находится `package.json` |
| Install Command  | `npm ci`                                         |
| Build Command    | `npm run build`                                  |
| Output Directory | `dist`                                           |
| Node.js Version  | 24.x                                             |

Локальная вложенная папка не меняет Root Directory: ориентируйтесь на структуру
репозитория в GitHub. Отдельный сервер для этого сайта не нужен. При
подключённой Git-интеграции Vercel создаёт preview для веток и обновляет
production из выбранной production-ветки. Этот репозиторий сам по себе ничего не
публикует.

Результат сборки также можно разместить на другом статическом хостинге.
Относительные пути ресурсов в `vite.config.js` позволяют использовать
подкаталог.

Документация: [Vite](https://vite.dev/guide/),
[Vercel для Vite](https://vercel.com/docs/frameworks/frontend/vite),
[Git-интеграция Vercel](https://vercel.com/docs/git).

## Перед публикацией

Страница является демонстрацией интерфейса. Настоящая регистрация, авторизация,
оплата и получение рыночных данных требуют отдельной интеграции. Формы не
отправляют заявки на сервер и не должны сообщать об успешной регистрации до
подключения API. Для запуска продукта нужно заменить демонстрационные данные
проверенными и подключить сервис регистрации.

Проверяйте сборку на ширинах 375, 768, 1024 и 1440 px: отсутствие
горизонтального переполнения, работу меню и клавиши Escape, карусели сделок, FAQ
и форм. Пройдите интерактивные элементы клавишами Tab и Enter; убедитесь, что
фокус виден и закрытые элементы не получают фокус. После изменения JavaScript
повторите эти сценарии через `npm run preview` и проверьте консоль браузера.

## Проверки в браузере

```bash
npm test
```

Playwright сам собирает production-версию, запускает `vite preview` на порту
4173 и проверяет её в браузере. Порт должен быть свободен. В Windows по
умолчанию используется установленный Microsoft Edge; в остальных системах —
Chromium, который нужно один раз установить:

```bash
npx playwright install chromium
```

Браузер можно переопределить переменной `PLAYWRIGHT_CHANNEL`, например `chrome`
или `chromium`. На Linux в CI используйте
`npx playwright install --with-deps chromium`.

Тесты проверяют ширины 320–1440 px, якорные ссылки, мобильную навигацию и её
прокрутку на низком экране, клавиатуру в FAQ, границы карусели, валидацию
e-mail, выбранный тариф, очистку формы и возврат фокуса после закрытия. Во всех
сценариях отслеживаются необработанные ошибки JavaScript.

Снимки production-версии сохраняются в `artifacts/desktop.png` (1440 × 1000) и
`artifacts/mobile.png` (375 × 900), полные страницы — в файлах с суффиксом
`-full`. При ошибке Playwright сохраняет трассировку и снимок в
`artifacts/test-results/`. Эти результаты не попадают в Git.
